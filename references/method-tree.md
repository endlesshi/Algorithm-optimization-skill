# 通用优化方法：两类对象与五个决策层次

本参考适用于一般算法、固定硬件上的程序优化，以及 FPGA、ASIC 和软硬件协同设计。LPU 的 Prefill、RMSNorm 仅作为案例，不作为分类边界。

## 组织原则：每一层按什么分类，顺序代表什么

以“改变了什么决策”为分类依据，将优化分为两类对象：

- **算**：计算工作及其执行，包括主体运算、索引、地址生成、指令生成和控制处理。
- **存**：数据保存及其流动，包括数据表示、存储访问、片内互连、芯片间通信和网络传输。

每类对象都按五个决策层次展开：

| 二级分支 | 要回答的问题 | 决策对象 |
| --- | --- | --- |
| 工作需求 | 必须做什么、做多少？ | 必要的运算、信息和访问 |
| 单次实现 | 一份工作具体怎么完成？ | 数值规则、数据表示及基本操作实现 |
| 资源组织 | 用什么资源、配置多少？ | 功能、容量、数量、宽度及连接结构 |
| 映射与调度 | 交给谁、放哪里、什么时候做？ | 工作与资源、位置及时间的对应关系 |
| 运行状态 | 开多少、跑多快、何时休眠？ | 工作点、启用范围及状态转换 |

阅读顺序是“确定工作 → 选择做法 → 配置资源 → 安排执行 → 选择运行状态”。这是分析顺序，不是强制的实施顺序，也不是收益排序。实际优化仍按[入口中的执行闭环](../SKILL.md)，从瓶颈和目标出发。

层级约定：

```text
一级：算 / 存
二级：工作需求 / 单次实现 / 资源组织 / 映射与调度 / 运行状态
三级：该类决策的组成部分
四级：对应机制、方法或候选选项
```

每组兄弟节点采用同一种分类依据，但不同子树可以采用不同顺序：

| 子树 | 三级组织与排序依据 |
| --- | --- |
| 工作需求 | 按减少工作的原因或信息需求划分 |
| 单次实现 | 从抽象表示到具体实现展开 |
| 资源组织 | 按结构组成展开 |
| 映射与调度 | 按“划分 → 映射 → 排序 → 重叠 → 协调”展开 |
| 运行状态 | 按运行控制的不同变量划分 |

四级有自然顺序时注明依据；没有自然顺序时明确作为并列候选。例如定点与浮点、总线与网格没有普遍成立的优先级。编号只用于定位和阅读。

## 独立标签：实现层次、修改条件与评价目标

这三个维度不混入主树分类，而为每个方案单独标注。

| 标签 | 可选内容 | 回答的问题 |
| --- | --- | --- |
| 实现层次 | 算法、软件、架构、电路、物理实现 | 在哪一层实现改动？ |
| 修改条件 | 固定硬件可做、需要已有硬件支持、需要修改硬件 | 当前平台是否允许实施？ |
| 评价指标 | 延迟、吞吐、能耗、功耗、面积、容量、成本 | 希望改善什么，付出什么代价？ |

性能、能耗和面积是横跨五层的评价指标，不单独成为优化机制分支。例如减少工作量、改变算术电路、调整资源数量和降低电压，都可能影响能耗。

| 决策层次 | 固定硬件时的例子 | 硬件可修改时的例子 |
| --- | --- | --- |
| 工作需求 | 换算法、复用结果、减少数据往返 | 根据可支持的算法与数据流共同确定工作需求 |
| 单次实现 | 选择指令、精度、表示和布局 | 定制运算电路、存储宏或通信接口 |
| 资源组织 | 选择平台已提供的资源配置，不能凭空新增端口或单元 | 调整单元、bank、端口、缓存、网络与队列结构 |
| 映射与调度 | 向量化、分块、任务分配、双缓冲 | 设计对应调度器，并与资源结构协同验证 |
| 运行状态 | 使用平台开放的频率、休眠等控制 | 设计电源域、时钟域及状态控制能力 |

固定硬件不代表所有配置都开放；硬件可修改也不代表没有面积、时序、功耗或可靠性限制。实现支持能力属于资源或电路设计，运行时选择何时启用该能力属于运行状态或调度。

工艺节点、封装、供电和散热是影响全系统的条件或设计变量。它们会同时改变算与存的可行方案，需要共同评估，不能仅按某个局部指标判断收益。

## 分类边界：主归属、关联分支与避免重复计数

树是决策检查框架，不是互不相关的物理模块清单，也不宣称穷尽所有未来技术。不同决策会相互影响，组合技术需要拆成具体改动后归类。

每个改动指定一个主归属，并记录关联分支：

| 改动 | 主归属 | 边界说明 |
| --- | --- | --- |
| 消除一次读取 | 存 → 工作需求 | 改变必要访问集合 |
| 合并相邻的小读取请求 | 存 → 单次实现 → 请求形成 | 所需数据未必减少，主要改变事务形成方式 |
| 改变数组内部排列 | 存 → 单次实现 → 数据布局 | 改变排列规则，不等于增加硬件资源 |
| 将数组放到不同 bank | 存 → 映射与调度 → 映射位置与路径 | 使用已有资源 |
| 增加 SRAM bank | 存 → 资源组织 → 访问接口 | 改变硬件结构 |
| 关闭暂时不用的 bank | 存 → 运行状态 | 改变现有资源的状态 |
| 增加派发队列深度 | 算 → 资源组织 | 配置供给和控制能力 |
| 改变队列中任务的执行优先级 | 算 → 映射与调度 | 改变已有能力的使用策略 |

控制工作也遵循五层：减少重复启动和准备属于工作需求；选择状态机或指令序列属于实现；配置派发资源属于资源组织；安排提交时机属于调度。不能因为控制与主体运算不同，就把它另列为与五层并列的机制。

还有几个需要按实际改动判断的边界：

- **工作量与实现**：改变整体求解步骤和实现一个基本操作不同，先固定分析粒度。
- **结构与使用**：设计多端口是资源组织；分配请求到现有端口是映射与调度。
- **需求与策略**：决定保存还是重算是工作需求；具体哪一块何时被替换是驻留策略。
- **排序与协调**：选择任务服务次序属于排序；处理冲突、屏障和交接协议属于协调。
- **算与存**：重计算替代读取同时增加算、减少存，分别记录变化，不把两边各自的估计时间收益直接相加。

树的四级包含具体方法示例，不代表这些技术名称在所有场景都只有一个归属。例如稀疏表示既可减少字节量，也可能支持跳过运算；前者归存的单次实现，后者归算的工作需求。

## 通用优化树

以下叶子是候选方向，不是必然有效的结论。任何改动都必须满足正确性、精度、可靠性和工程约束。

### 算：计算工作及其执行

```text
算
│
├── 1. 工作需求：哪些运算必须做，做多少？
│   │   分类：按减少工作量的原因划分
│   │   顺序：不必做 → 不必重做 → 换方法做 → 允许少求解
│   │
│   ├── 1.1 消除不需要的工作
│   │   ├── 结果不需要：删除无用输出及其计算
│   │   ├── 输入不需要：跳过无效区域、padding、已知零贡献
│   │   └── 后续不需要：剪枝、提前终止、按需展开
│   ├── 1.2 复用已经完成的工作
│   │   │   以下按复用范围从小到大排列
│   │   ├── 表达式范围：公共子表达式复用
│   │   ├── 单次任务范围：循环不变量、共享中间结果
│   │   └── 跨任务范围：结果缓存、固定部分预计算、增量更新
│   ├── 1.3 在相同求解要求下减少步骤
│   │   │   以下为并列机制
│   │   ├── 利用问题结构：对称、稀疏、可分离、特殊参数
│   │   ├── 改变求解算法：降低复杂度、改变计算域或问题分解
│   │   └── 改善求解过程：更好的初始化、收敛方法和搜索策略
│   └── 1.4 在允许范围内降低求解要求
│       │   以下按放宽的要求分类，无优先顺序
│       ├── 范围：只处理部分样本、候选或输出
│       ├── 分辨率：降低离散精细程度或表示阶数
│       └── 精确程度：放宽误差或停止条件，使用近似求解
│
├── 2. 单次实现：一个选定的基本操作如何实现？
│   │   分类与顺序：数值规则 → 操作实现 → 电路实现
│   │
│   ├── 2.1 数值规则
│   │   ├── 数值类型：整数、定点、浮点
│   │   ├── 精度配置：操作数、内部中间值、累加与输出精度
│   │   └── 数值处理：舍入、饱和、溢出及近似算术规则
│   ├── 2.2 操作实现
│   │   │   以下为并列候选
│   │   ├── 原生操作：匹配指令、内建功能或专用操作
│   │   ├── 等价替换：强度削减、不同指令序列
│   │   ├── 组合实现：查表、插值、迭代求值
│   │   └── 融合实现：多个基本操作共用中间数据通路
│   └── 2.3 电路实现
│       │   以下按逻辑到物理排列
│       ├── 逻辑结构：加法器、乘法器、比较器等结构选择
│       ├── 逻辑优化：布尔化简、常量专用化、减少逻辑深度
│       └── 物理实现：单元选择、驱动、扇出及局部布局布线
│
├── 3. 资源组织：建立什么计算系统？
│   │   分类与顺序：功能 → 规模 → 连接共享 → 内部结构
│   │
│   ├── 3.1 功能组成
│   │   ├── 运算资源：标量、向量、矩阵及专用功能
│   │   └── 控制资源：取指、译码、派发及调度能力
│   ├── 3.2 资源规模
│   │   ├── 各类单元数量及由此形成的配置比例
│   │   └── 单元处理宽度
│   ├── 3.3 连接与共享关系
│   │   ├── 私有或共享资源
│   │   ├── 集中式或分布式组织
│   │   └── 单元之间的操作数转发与协作接口
│   └── 3.4 单元内部执行结构
│       ├── 流水级划分与寄存器配置
│       ├── 运算步骤采用空间展开或时间复用
│       └── 内部缓冲、队列与背压接口
│
├── 4. 映射与调度：将工作安排到已有资源上
│   │   分类与顺序：划分 → 映射 → 排序 → 重叠 → 协调
│   │
│   ├── 4.1 划分工作单位
│   │   ├── 划分依据：按数据、功能或任务划分
│   │   └── 划分粒度：分块、批次、拆分与合并
│   ├── 4.2 映射到资源
│   │   ├── 选择适合的执行单元
│   │   ├── 匹配执行宽度与计算形状
│   │   └── 分配负载，减少尾部和资源闲置
│   ├── 4.3 安排顺序
│   │   ├── 在依赖允许范围内重排
│   │   ├── 优先推进关键路径
│   │   └── 选择静态顺序或动态就绪调度
│   ├── 4.4 重叠执行
│   │   ├── 单元内：独立指令交错、多累加链
│   │   ├── 单元间：独立任务并行
│   │   └── 阶段间：软件流水线、跨任务阶段重叠
│   └── 4.5 协调执行
│       ├── 同步范围：全局、局部或依赖对象级
│       ├── 同步粒度：整任务、分块或单个事件
│       └── 竞争处理：优先级、公平性与背压响应
│
└── 5. 运行状态：资源当前如何工作？
    │   分类：工作点、启用范围、状态转换，三者是不同决策
    │
    ├── 5.1 工作点
    │   └── 选择电压、频率和受支持的运行模式
    ├── 5.2 启用范围
    │   └── 启用哪些单元、通道和数据通路
    └── 5.3 状态转换
        ├── 何时进入时钟门控、电源门控或操作数隔离状态
        └── 何时恢复，如何控制唤醒延迟和切换成本
```

基本操作的粒度要先确定。例如，改用 FFT 算法属于“工作需求”；如何实现其中一个乘法属于“单次实现”。不能通过随意改变分析粒度，将同一收益重复记在两层。

“消除无用工作”保持原有求解要求；“降低求解要求”必须得到需求允许。提前停止若已有充分条件证明不影响要求，属于前者；若放宽误差门槛，属于后者。复用范围是示例归属，某些预计算也可以发生在单次任务内部，应按实际范围标注。

### 存：数据保存及其流动

这里“减少搬运”指减少指定层级的搬运、读写次数；压缩和量化属于缩小数据表示；布局与请求合并改善访问效率；预取和双缓冲改变搬运时机与重叠。这些方法可以组合，分别核对对应机制，再看整体收益。次数注明统计单位：删除重复读取减少必要访问，合并请求减少传输请求数。

```text
存
│
├── 1. 工作需求：必须保留什么，必须访问多少次？
│   │   分类：信息集合、访问集合、保留策略
│   │   顺序：先确定需要什么，再判断怎么获得和保留
│   │
│   ├── 1.1 缩小必须保留的信息集合
│   │   ├── 删除不会使用的字段、结果和冗余副本
│   │   └── 完整中间数据改为必要状态或流式片段
│   ├── 1.2 减少必须执行的访问次数
│   │   ├── 删除无效访问：无用读取、写入、初始化和复制
│   │   ├── 复用已有数据：一次获得，多次使用或多方共享
│   │   └── 合并数据更新：减少重复读写和中间往返
│   └── 1.3 选择信息的获得与保留方式
│       │   以下为替代选项，不是实施步骤
│       ├── 保存后复用
│       ├── 使用时重新读取
│       └── 使用时重新生成或重新计算
│
├── 2. 单次实现：一份信息怎样编码，一次访问怎样完成？
│   │   分类与顺序：表示 → 布局 → 请求 → 基本实现
│   │
│   ├── 2.1 信息表示
│   │   │   以下是可组合的编码维度，不是互斥技术类别
│   │   ├── 数值编码：位宽、量化和位打包
│   │   ├── 结构编码：稀疏、索引、参数化或规则化表示
│   │   └── 冗余编码处理：压缩、差分和字典等方式
│   ├── 2.2 数据布局
│   │   ├── 元素组织：维度顺序、行列布局、结构体布局
│   │   ├── 空间间隔：步长、对齐和填充
│   │   └── 块内组织：打包、交错和局部重排
│   ├── 2.3 请求形成
│   │   ├── 请求粒度：大小、突发长度与分包
│   │   ├── 请求合并：连续或相邻访问的聚合
│   │   └── 协议封装：元数据、握手和有效载荷比例
│   └── 2.4 基本存储与传输实现
│       ├── 存储：介质、存储单元和存储宏选择
│       ├── 通信：接口电路、链路编码与传输方式
│       └── 物理：读写时序、驱动与局部布局布线
│
├── 3. 资源组织：建立什么存储和通信系统？
│   │   分类：按系统组成部分划分
│   │   顺序：存储节点 → 访问接口 → 连接网络 → 控制缓冲
│   │
│   ├── 3.1 存储节点
│   │   ├── 层级：寄存器、缓存、暂存器和外部存储
│   │   ├── 各层容量与实例数量
│   │   └── 私有、共享及一致性域组织
│   ├── 3.2 访问接口
│   │   ├── bank 与端口组织
│   │   ├── 通道数量
│   │   └── 每个接口的数据宽度
│   ├── 3.3 连接网络
│   │   ├── 拓扑：总线、环、交叉开关、网格等
│   │   ├── 连接规模：链路数量、宽度和端点位置
│   │   └── 连接能力：直连、旁路、广播和多播
│   └── 3.4 控制与缓冲
│       ├── 控制器、DMA 和预取器配置
│       ├── 队列、缓冲与在途请求容量
│       └── 一致性、仲裁和流量控制的实现能力
│
├── 4. 映射与调度：数据和访问如何使用已有资源？
│   │   分类与顺序：划分 → 映射 → 排序 → 重叠 → 协调
│   │
│   ├── 4.1 划分数据和传输任务
│   │   ├── 数据分区与工作集分块
│   │   └── 选择搬运批次和流水处理单位
│   ├── 4.2 映射位置与路径
│   │   ├── 数据到层级、节点、bank 和通道的放置
│   │   ├── 缓冲区分配、原地更新和空间复用
│   │   └── 路径选择、数据迁移和计算靠近数据
│   ├── 4.3 安排访问与驻留顺序
│   │   ├── 遍历顺序与复用顺序
│   │   ├── 缓存准入、替换和写回时机
│   │   └── 请求排序、热点分散和服务优先级
│   ├── 4.4 重叠数据准备与使用
```

## 组合方法与代价权衡

融合、分块、专用化、脉动阵列等是组合技术。用五层解释它们具体改变了什么，不将技术名称直接当作独立机制。

| 方案 | 主归属与关联分支 | 期望收益与代价 |
| --- | --- | --- |
| 算子融合 | 存 → 工作需求；可能关联算的工作需求和映射与调度 | 减少中间往返、启动；可能增加同时存活的数据、资源压力 |
| 分块 | 算/存 → 映射与调度 → 划分 | 匹配资源、提高复用；可能增加边界处理和调度开销 |
| 双缓冲 | 存 → 映射与调度 → 重叠 | 隐藏搬运等待；增加空间和同步复杂度 |
| 重计算替代保存 | 存 → 工作需求 → 获得与保留方式；关联算的工作需求 | 减少容量或传输需求；增加运算 |
| 固定形状专用化 | 按实际改动归算的工作需求、单次实现或映射与调度 | 消除动态工作、改进实现；增加代码和适用范围限制 |
| 数据压缩 | 存 → 单次实现 → 信息表示；关联算的工作需求 | 减少字节量；增加编解码、元数据或精度代价 |
| 增加计算单元 | 算 → 资源组织 → 资源规模 | 提高潜在并行能力；增加面积、功耗和供数压力 |
| 加深硬件流水线 | 算 → 资源组织 → 内部执行结构 | 可能提高频率和吞吐；增加寄存器、控制成本及可能的单次延迟 |
| 脉动阵列 | 算 → 资源组织；关联算的调度、存的组织与映射 | 计算并行和局部传递；受映射、利用率和输入供给约束 |
| 预打包或预计算 | 分别归存的单次实现、算的工作需求；提前执行关联调度 | 改善在线路径；承担准备成本、空间和失效更新成本 |

预计算只是移动或摊销工作，并不意味着整个系统不再付出成本。双缓冲在已有存储上实现时属于映射与调度；若需要新增 SRAM，则新增硬件作为资源组织的配套改动单独记录。

最终比较目标范围内的净收益，并验证瓶颈是否转移。例如增加乘法器后，如果数据供给没有跟上，潜在并行能力未必变成有效吞吐。仿真、综合、布局布线和真实运行的证据不能互相冒充。

方法筛选与验证优先级见 [测量与决策](measurement-and-decisions.md)；平台示例见 [案例](cases.md)。
