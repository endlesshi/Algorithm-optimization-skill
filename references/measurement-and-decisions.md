# 测量、瓶颈诊断与决策

用途：解读报告、选择下一项检查、排序方案、判断接受或停止。来源于方法总结第五章和第七章。

## 指标与边界

| 指标 | 必须说明 |
| --- | --- |
| 延迟/总耗时 | 工作单位、起止事件、排队/准备/布局转换/上传下载/启动/同步是否包含 |
| 吞吐 | 有效完成的工作量、观察窗口、并发、冷/稳态；批量平均不等于独立调用延迟 |
| 周期 | 时钟域、频率、计数范围；变频、多时钟域或不同模型不能用一个频率统一换算 |
| II | 任务粒度与流水边界；区分目标II、工具调度II和实际启动间隔；派发配置不是任务II |
| 流量/带宽 | 层级、方向、窗口；有效字节、padding/协议/重复访问后的物理字节分开 |
| 利用率 | 资源忙碌率、忙时有效并行度、有效产出分开；padding不计作有用工作 |
| 空间 | 物理大小、对齐和同时存活范围；复用区不重复累加 |
| 能耗/功耗/面积 | 范围、工艺、约束、实现阶段；架构估计、仿真、综合、布局布线和硅后实测不混用 |

异步系统必须选择目标对应的完成事件，提交完成不代表执行完成。事件累计时长可以超过墙钟时间；忙碌时间用同资源事件区间并集，阶段重叠时不能简单相加。共享硬件各模块的“持续时间”不必等于独占服务时间。

泳道图需注明时间单位、资源、颜色和模块归属，以及色块是提交、排队还是执行。accept-to-done 可能包含等待；仅凭色块重叠不能证明算术并行。预取跨阶段时，检查归账脚本与窗口是否变化。带采集扰动的诊断运行与正常性能运行分别解释。

## 按需测量

| 条件 | 选择 |
| --- | --- |
| 固定配置且有确定性依据的仿真 | 一次完整有效运行通常够用，不固定增加预热或重复 |
| 冷启动是目标 | 保留初始化和冷状态，不用预热排除这部分成本 |
| 稳态是目标且启动会干扰 | 按需预热或选稳态窗口，记录依据 |
| 硬件有波动、结果矛盾或收益接近噪声 | 定向检查频率/温度/负载，按需重复或交替A/B |
| 机制是请求数、指令数或调度II | 查相应计数、代码或报告，不强制完整trace |
| 连续状态或边界改变 | 扩展相关序列/边界；重复同一输入不能代替覆盖 |

只测一次就报告单次值。不用一个样本证明“稳定提升”，不强制计算p95/p99；尾延迟目标才需要相应样本与窗口。仿真含随机仲裁或未控制状态时先核实种子及波动。主目标、正确性和对照条件已足以决策且无关键异常时停止测量。

比较耗时/周期：`加速比=T_old/T_new`，`降幅=1−T_new/T_old`，`节省=T_old−T_new`。吞吐提升：`Q_new/Q_old−1`，不要与耗时降幅混用。先逐用例报告；只有需求定义权重或汇总规则时才汇总。

若方案本身改变精度、资源数量或频率，清楚记录改变及代价；不将其描述成同配置纯代码收益。模型重放、单算子实测和完整系统运行分别建立对照。

## 诊断和下一项检查

按“目标差距 → 主要贡献/关键路径 → 瓶颈原因 → 区分假设”追踪。

原因可来自工作量、基本操作成本、资源能力、映射、依赖/竞争和运行状态。模块耗时大不等于可改善的整体收益最大，资源连续忙也可能在做冗余工作。

每项新检查回答：能排除哪些原因？结果会改变方案选择吗？成本多少？优先已有证据，再补局部事件/小实验；无法区分假设的更多总体利用率没有帮助。

例：计算有空隙，先查数据就绪与指令提交时刻。供数迟、控制核提交迟、同步依赖及资源竞争需要不同方法。只有确认数据准备晚且容量、生命周期和通路允许时，双缓冲才成为有依据的候选。

## 候选排序与边界

从 [方法树](method-tree.md) 扫描相关分支，按瓶颈匹配、前提约束、整体直接净收益、关键不确定性、实施成本选择。必要前置改动与最终改动一起评价；收益接近时优先简单方案，不能仅凭方法树顺序或最熟悉的技巧排序。

在无重叠且其他部分不变时，局部占比p、局部加速s对应：

```text
整体加速 = 1 / ((1−p) + p/s)
总耗时降幅 = p × (1−1/s)
```

占60%的模块快1.05倍，整体约少2.86%；占20%的模块快2倍，整体少10%。有重叠、共享资源竞争或新增成本时，用依赖和时间线重估，不直接套占比公式。

计算/带宽下界仅在工作确实不可消除、峰值可用且边界相同时成立。计算与搬运可重叠时，独立资源服务下界通常取最大值而非相加；真正串行的依赖另算。容量/依赖链也可能支配结果。标注理想下界，不将其当实测预测或未经证明的全局最优。

## 假设、验证与接受

一轮记录“瓶颈原因 → 协同改动 → 预期机制变化 → 整体收益”。可同时改变布局、分块、请求和同步；若整体假设成立且满足验收，无需为了形式将每个改动拆开重跑。若结果矛盾或需回答边际贡献，再定向拆分。

验证正确性、目标收益与代价、关键机制。改动涉及：

- 缓冲复用/异步：检查生产消费区间、就绪与释放、物理覆盖、初始化/排空和阶段交接；不能只凭源码SET/WAIT顺序推断执行顺序。
- 状态更新：检查相关连续调用、对齐边界、容量尾部和约定不可改区域。
- 精度/算法变化：独立参考、特殊值和原精度契约；有限输入逐位相同不推广到所有输入。
- 专用路径：明确适用前提及非适用输入的正确处理。
- 正式接入：确认运行的源码、产物、配置或实际指令对应已测候选。

运行状态（完成/超时/错误/未运行）、检查结果（通过/失败/未检查）、候选决策（接受/条件接受/撤回/待验证）和项目停止状态分开记录。通过正确性且满足收益、资源和回退约束才接受；接受后重新识别瓶颈。

## 停止与恢复

| 停止状态 | 依据 |
| --- | --- |
| 达标 | 正确性、目标和全部硬约束通过 |
| 当前约束下不可达 | 可靠下界、容量或依赖证明；检查允许的方法能否消除所假设的必要工作 |
| 缺条件 | 具体缺失的权限、硬件、工具、信息或资源 |
| 投入不划算 | 剩余收益与实现、验证和维护成本的比较 |
| 暂未找到方案 | 已尝试范围、失败假设和未解决方向；不声称全局不可优化 |

保留尚未满足的要求、有效基线和恢复条件。条件未变不重复证伪方案；输入、资源或约束变化后可重新评估。按 [复现与交付](reproducibility-and-delivery.md) 保存证据。
